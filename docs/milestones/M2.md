# M2 — QUIC adapter

Status: complete on the current worktree.

`internal/quictransport` now adapts `github.com/quic-go/quic-go v0.62.0` to
the private `internal/transport` interfaces. Its configuration clones TLS
state, rejects insecure verification and pre-TLS-1.3 configurations, fixes
ALPN to `sgsp/1`, uses normal `Dial` rather than an early-data API, disables
`Allow0RTT`, negotiates QUIC datagrams explicitly, and caps configured stream
and connection flow-control windows. Concrete quic-go types remain private.

The localhost integration suite verifies:

- trusted versus untrusted server certificates and TLS/ALPN policy;
- bidirectional and unidirectional stream transfer;
- negotiated datagrams without a reliable fallback;
- stream reset/cancellation and read deadlines;
- advertised inbound-stream credit; and
- normal (non-0-RTT) adapter configuration.

Checks run from the module root:

```text
go test -count=1 ./internal/quictransport       exit 0
go test -count=1 ./...                          exit 0
go test -race -count=1 ./...                    exit 0
go vet ./...                                    exit 0
gofmt -l .                                      exit 0 (no output)
```

The managed sandbox prohibits UDP socket creation, so the real-QUIC commands
were run with the explicit localhost-UDP permission. quic-go reported that the
host receive buffer could not reach its preferred 7 MiB size (416 KiB actual);
this did not affect adapter correctness tests, but it is recorded for M8
capacity measurements. NAT rebinding is not claimed by this milestone and is
deferred to the M5 adapter behavior test specified by the architecture.
